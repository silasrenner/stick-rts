EXACT PROGRESSION RULE
======================

For Hard's unit-utility path, buildIndex advances exactly once if and only if:

  1. a selected candidate is a normal unit; and
  2. authoritative buyUnit() execution returns { ok: true }.

Conceptually:

  decision
  -> inspect build-cycle preference
  -> evaluate feasibility / utility
  -> select normal unit
  -> buyUnit() succeeds
  -> increment buildIndex once

It does not advance merely because:

  - a decision timer fires;
  - all normal candidates are infeasible;
  - gold is insufficient;
  - the production queue is unavailable;
  - no normal unit is selected;
  - execution fails after feasibility inspection;
  - a non-unit fallback occurs.

The bounded latest-decision record exposes:

  buildIndexBefore
  buildCycleKind
  selected candidate
  purchase result
  didBuildIndexAdvance
  buildIndexAfter
  buildIndexReason

Reasons are:

  successful-normal-unit-commit
  no-normal-unit-commit
