Hard Build Army combat-readiness summary — 2026-08-18
========================================================

Implemented
-----------
Hard's existing Build Army unit-utility weights now prefer feasible combat
while the existing strategic goal is Build Army (which already means the team
is below minArmyToAttack).

  Before:
    recoveryProgress: 0
    combatEfficiency: 0
    counterValue: 1.00
    buildCycleBias: 0.25

  After:
    recoveryProgress: 1.00
    combatEfficiency: 0.75
    counterValue: 1.00
    buildCycleBias: 0.10

No signal was renamed. recoveryProgress remains the existing binary combat
signal: warrior/archer = 1 and miner = 0.

Behavior preserved
------------------
- Enemy vision, memory duration, composition semantics, and unknown-state
  boundary are unchanged.
- No hidden enemy information was restored.
- Existing counters still choose between warrior and archer when valid enemy
  composition is available.
- Feasibility filtering remains authoritative.
- The build cycle remains a secondary preference.
- Goals, commands, minArmyToAttack, recovery, zero-miner emergency, build-index
  advancement, turrets, heroes, queue/cap behavior, economy, combat, Raven, and
  scouting were not changed.

Deterministic proof
-------------------
A new real decision-path fixture uses:

  goal: Build Army
  force: one miner, zero combat
  build-cycle slot: miner
  enemy composition: unknown / {}

It initially failed as intended: the old utility selected miner with a 0.25
cycle-only score.

It now passes:

  warrior: readiness 1, efficiency 1, total 1.75
  miner:   readiness 0, cycle-only total 0.10
  selected: warrior

Focused tests passed for Build Army readiness, valid counter choice, infeasible
counter fallback, Recover, zero-miner emergency, cap fallback, deterministic
selection, observability, goal selection, build-index progression, perception
and memory, team vision, production, turrets, defense, and headless invariants.

Candid outcome
--------------
The narrow Build Army change works at its intended seam: it no longer lets an
unknown enemy composition reduce Build Army to a miner-containing cycle.

It improves liveness but does not restore healthy cohort liveness: 4 of 5
matches remain unresolved. Per scope, no Attack standing-force maintenance,
Raven, scouting utility, or additional tuning was added.

The next likely question, requiring separate approval, is whether the existing
Attack goal needs a narrow friendly-state standing-force maintenance rule.
